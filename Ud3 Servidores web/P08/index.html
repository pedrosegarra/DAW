    Práctica P08 (guiada): Publicación en Docker Hub con versiones

    Centro: IES El Caminàs
    Módulo: Despliegue de Aplicaciones Web
    Profesor: Pedro Segarra
    Curso: 2026/2027

    Objetivo de la práctica

    Construir una imagen propia de un servidor web, publicarla en Docker Hub con varias versiones y desplegarla en cualquier máquina con docker compose, sin copiar ningún fichero: solo descargando la imagen.

    Al terminar sabrás:

    Concepto Apartado
    Diferencia entre imagen y contenedor 3 y 4
    Nombre completo de una imagen: registro/usuario/repositorio:etiqueta 5
    Autenticarse en un registro con un token 6
    push y pull 7 y 8
    Varias versiones de una imagen y qué es latest 9
    Rollback: volver a una versión anterior 10
    Digest: el identificador que no cambia nunca 11

    Cómo usar esta guía

    Está resuelta paso a paso. Escribe tú cada comando (no copies y pegues sin leer), compara lo que te sale con la salida esperada y responde a las preguntas que hay en cada apartado.
    Al final, en el reto, tendrás que repetir el proceso sin la guía. Eso es lo que se entrega.

    Sustituciones obligatorias

    En todos los comandos, cambia:

    • usuario por tu usuario de Docker Hub (en minúsculas).
    • xyz por tus iniciales (en minúsculas). Ejemplo: Pedro Segarra Cabedo → psc.

    Requisitos previos

    • Docker instalado en el equipo local (docker --version).
    • Haber hecho las prácticas anteriores de la unidad (Dockerfile y docker compose).
    • Una cuenta en Docker Hub (la creas en el apartado 1).

    1. Preparar la cuenta de Docker Hub

    1. Crea una cuenta gratuita en https://hub.docker.com. Tu nombre de usuario es el usuario de esta guía.
    2. Crea un token de acceso: Account settings → Personal access tokens → Generate new token.
      • Descripción: aula-daw
      • Permisos: Read & Write
    3. Copia el token y guárdalo en un sitio seguro.

    El token solo se muestra una vez

    Si lo pierdes, tendrás que generar otro.

    ¿Por qué un token y no la contraseña?

    Si alguien te roba el token (por ejemplo, porque te dejaste la sesión abierta en un ordenador del aula), lo revocas y ya está. Tu contraseña sigue segura y no hace falta cambiarla.

    2. Crear la carpeta del proyecto

    mkdir -p ~/servidorxyz
cd ~/servidorxyz

    Al final tendrás esta estructura:

    servidorxyz/
├── Dockerfile
├── index.html
└── compose.yaml        ← lo crearás en el apartado 8

    ¿compose.yaml o docker-compose.yml?

    Los dos funcionan. compose.yaml es el nombre actual; docker-compose.yml es el antiguo, que se sigue aceptando por compatibilidad. Usa solo uno en cada carpeta.

    3. Escribir la página y el Dockerfile

    3.1. index.html

    <!DOCTYPE html>
<html lang="es">
<head>
  <meta charset="UTF-8">
  <title>Servidor de Nombre Apellidos</title>
  <style>
    body { font-family: sans-serif; background: #3f51b5; color: #fff;
           display: grid; place-items: center; height: 100vh; margin: 0; }
    .caja { background: #009688; padding: 2rem 3rem; border-radius: 12px; text-align: center; }
  </style>
</head>
<body>
  <div class="caja">
    <h1>Servidor de Nombre Apellidos</h1>
    <p>IES El Caminàs · Despliegue de Aplicaciones Web</p>
    <p><strong>Versión 1.0</strong></p>
  </div>
</body>
</html>

    Personaliza

    Cambia Nombre Apellidos por tu nombre. Así se verá que la imagen es tuya.

    3.2. Dockerfile

    # Imagen base oficial de nginx, con la versión FIJADA (nunca "latest" en una imagen base)
FROM nginx:1.28-alpine

# Metadatos de la imagen (estándar OCI)
LABEL org.opencontainers.image.authors="Nombre Apellidos"
LABEL org.opencontainers.image.description="Servidor web de xyz para la práctica de Docker Hub"

# Copiamos nuestra web al directorio que sirve nginx en esta imagen
COPY index.html /usr/share/nginx/html/index.html

# Documenta el puerto que escucha el contenedor (no lo publica: eso lo hace -p o compose)
EXPOSE 80

    Ojo con el directorio

    La imagen oficial de nginx sirve las webs desde /usr/share/nginx/html, no desde /var/www/html como una instalación normal en Debian/Ubuntu.

    Pregunta 1

    ¿Por qué fijamos nginx:1.28-alpine en lugar de poner nginx:latest? ¿Qué podría pasar dentro de seis meses si usaras latest?

    4. Construir la imagen y probarla en local

    docker build -t servidorxyz .

    Salida esperada (al final):

     => exporting to image
 => => naming to docker.io/library/servidorxyz:latest

    Fíjate en ese nombre

    docker.io/library/servidorxyz:latest. Como no has indicado usuario, Docker la ha llamado como si fuera una imagen oficial (library). Si intentas subirla así, no te dejará. Lo arreglamos en el apartado 5.

    Lanza un contenedor y comprueba que funciona:

    docker run -d --name prueba -p 8080:80 servidorxyz
curl http://localhost:8080

    Resultado esperado

    Sale el HTML de tu página. En el navegador, http://localhost:8080 muestra tu nombre y Versión 1.0.

    Cuando funcione, borra el contenedor (la imagen se queda):

    docker rm -f prueba
docker images | grep servidorxyz

    Pregunta 2

    Acabas de borrar el contenedor, pero la imagen sigue ahí. Explica con tus palabras la diferencia entre imagen y contenedor.

    5. Poner a la imagen su nombre completo

    Para subir una imagen a Docker Hub, su nombre tiene que empezar por tu usuario:

    docker.io / usuario / servidorxyz : 1.0
 registro   usuario   repositorio   etiqueta

    docker.io es el registro por defecto, así que no hace falta escribirlo.

    Damos dos etiquetas a la misma imagen:

    docker tag servidorxyz usuario/servidorxyz:1.0
docker tag servidorxyz usuario/servidorxyz:latest
docker images | grep servidorxyz

    Salida esperada:

    usuario/servidorxyz   1.0      a1b2c3d4e5f6   2 minutes ago   48MB
usuario/servidorxyz   latest   a1b2c3d4e5f6   2 minutes ago   48MB
servidorxyz           latest   a1b2c3d4e5f6   2 minutes ago   48MB

    Pregunta 3

    Las tres líneas tienen el mismo IMAGE ID. ¿Cuántas imágenes hay realmente en el disco? ¿Qué es entonces una etiqueta?

    6. Iniciar sesión en Docker Hub

    Usamos --password-stdin para que el token no quede en el historial de la terminal:

    read -s TOKEN          # pega el token y pulsa Intro (no se verá nada)
echo "$TOKEN" | docker login -u usuario --password-stdin
unset TOKEN

    Salida esperada:

    Login Succeeded

    Nunca pongas el token en el comando

    docker login -p MITOKEN deja el token guardado en ~/.bash_history y visible en la lista de procesos.

    7. Publicar la imagen

    docker push usuario/servidorxyz:1.0
docker push usuario/servidorxyz:latest

    Salida esperada del primer push:

    The push refers to repository [docker.io/usuario/servidorxyz]
5f70bf18a086: Pushed
...
1.0: digest: sha256:9c3f...e21a size: 1989

    Segundo push

    En el push de latest verás Layer already exists: las capas ya están subidas y solo se añade la etiqueta nueva.

    Entra en https://hub.docker.com/r/usuario/servidorxyz y comprueba:

    • Que aparecen las etiquetas 1.0 y latest.
    • Que en Settings el repositorio es Public.

    Obligatorio

    Si el repositorio es privado, nadie más podrá descargar tu imagen.

    Pregunta 4

    Apunta el digest que te ha dado el push de la 1.0. Lo usarás en el apartado 11.

    8. Desplegar desde Docker Hub con compose.yaml

    Ahora simulamos lo que hará el profesor: una máquina sin tu imagen que la descarga de Docker Hub.

    8.1. Borrar todo lo local

    docker rmi servidorxyz usuario/servidorxyz:1.0 usuario/servidorxyz:latest
docker images | grep servidorxyz      # no debe salir nada

    8.2. Crear compose.yaml

    services:
  webxyz:
    image: usuario/servidorxyz:1.0   # sin "build:": la imagen viene de Docker Hub
    container_name: webxyz
    ports:
      - "8080:80"
    restart: unless-stopped

    8.3. Levantarlo

    docker compose up -d

    Salida esperada:

    [+] Running 2/2
 ✔ webxyz Pulled
 ✔ Container webxyz  Started

    La prueba

    La palabra Pulled demuestra que la imagen ha venido de Docker Hub.
    curl http://localhost:8080 debe decir Versión 1.0.

    docker compose y no docker-compose

    docker compose (con espacio) es el comando actual. docker-compose (con guion) es la versión antigua, que ya no se mantiene.

    9. Publicar una nueva versión: la 1.1

    Cambia en index.html la línea de la versión:

        <p><strong>Versión 1.1</strong> · Ahora con más estilo</p>

    Construye la nueva versión con sus dos etiquetas de una vez y súbela:

    docker build -t usuario/servidorxyz:1.1 -t usuario/servidorxyz:latest .
docker push usuario/servidorxyz:1.1
docker push usuario/servidorxyz:latest

    Mira Docker Hub: ahora tienes tres etiquetas: 1.0, 1.1 y latest.

    Pregunta 5

    ¿A qué versión apunta ahora latest? ¿Ha desaparecido la 1.0 de Docker Hub?

    9.1. Actualizar el despliegue

    Cambia en compose.yaml la etiqueta:

        image: usuario/servidorxyz:1.1

    docker compose up -d
curl http://localhost:8080      # debe decir "Versión 1.1"

    Compose detecta que la imagen ha cambiado y recrea el contenedor.

    Cada cambio, un nuevo build y push

    Si cambias algo y no haces build + push, en Docker Hub seguirá la versión vieja, y es la que descargará el profesor.

    10. Rollback: volver a la 1.0

    Imagina que la 1.1 tiene un error grave en producción. Volver atrás es tan fácil como cambiar la etiqueta:

        image: usuario/servidorxyz:1.0

    docker compose up -d
curl http://localhost:8080      # vuelve a decir "Versión 1.0"

    Pregunta 6

    ¿Por qué el rollback ha sido inmediato y no has tenido que volver a construir nada?

    Pregunta 7

    Si en el compose.yaml hubieras puesto latest, ¿podrías hacer este rollback? ¿Qué versión se descargaría un compañero que lo levantara hoy? ¿Y si lo levantara después de que publicaras una 1.2?

    11. El digest: el identificador que no se puede cambiar

    Una etiqueta es móvil: tú mismo has movido latest de la 1.0 a la 1.1. Incluso podrías volver a subir otra imagen distinta con la etiqueta 1.0. El digest (sha256:…), en cambio, se calcula a partir del contenido: si el contenido cambia, cambia el digest.

    Mira los digests de tus imágenes:

    docker images --digests | grep servidorxyz

    Despliega usando el digest de la 1.0 que apuntaste en el apartado 7:

        image: usuario/servidorxyz@sha256:9c3f...e21a

    docker compose up -d
curl http://localhost:8080      # Versión 1.0, garantizado

    Pregunta 8

    ¿En qué situaciones te interesaría desplegar por digest en lugar de por etiqueta?

    12. Cerrar la sesión

    En los ordenadores del aula, siempre:

    docker compose down
docker logout

    Revoca el token

    Si ya no vas a usarlo, bórralo en Docker Hub: Personal access tokens → Delete.

    13. Si trabajas en un Mac con procesador Apple (M1, M2, M3…)

    Tu Mac construye imágenes para ARM (linux/arm64). Los PC del aula y la mayoría de servidores son x86 (linux/amd64), y tu imagen no arrancará en ellos (exec format error).

    Construye para las dos arquitecturas y súbela en un solo paso:

    docker buildx build --platform linux/amd64,linux/arm64 \
  -t usuario/servidorxyz:1.1 -t usuario/servidorxyz:latest \
  --push .

    Comprobación

    En Docker Hub verás OS/ARCH: 2 junto a la etiqueta.

    14. Problemas comunes y soluciones

    denied: requested access to the resource is denied

    • Causa: la imagen no empieza por tu usuario, o no has hecho docker login.
    • Solución: revisa los apartados 5 y 6.

    invalid reference format: repository name must be lowercase

    • Causa: hay mayúsculas en el nombre.
    • Solución: todo en minúsculas: servidorxyz, no ServidorXYZ.

    unauthorized: incorrect username or password

    • Causa: el token es incorrecto o no tiene permiso de escritura.
    • Solución: genera otro con permisos Read & Write.

    pull access denied … repository does not exist

    • Causa: el repositorio es privado o el nombre está mal escrito.
    • Solución: ponlo Public en Settings y revisa el nombre.

    Bind for 0.0.0.0:8080 failed: port is already allocated

    • Causa: otro contenedor está usando el puerto 8080.
    • Solución: docker ps y bórralo, o cambia a "8081:80".

    Sale la versión antigua

    • Causa: no has hecho build + push después del cambio, o compose está usando la imagen local.
    • Solución: 
      docker compose pull
docker compose up -d

    exec format error

    • Causa: imagen ARM construida en un Mac.
    • Solución: apartado 13.

    15. Lista de comprobación final

    • En hub.docker.com/r/usuario/servidorxyz aparecen 1.0, 1.1 y latest, y el repositorio es público.
    • Sin la imagen en local, docker compose up -d muestra Pulled y arranca webxyz.
    • http://localhost:8080 muestra tu nombre y la versión que pone en el compose.yaml.
    • Sabes pasar de la 1.1 a la 1.0 cambiando una sola línea.
    • Sabes desplegar una versión por digest.
    • Has respondido a las 8 preguntas.

    16. Resumen de comandos

    # 1) Construir y probar en local
docker build -t servidorxyz .
docker run -d --name prueba -p 8080:80 servidorxyz
docker rm -f prueba

# 2) Etiquetar con el nombre de Docker Hub
docker tag servidorxyz usuario/servidorxyz:1.0
docker tag servidorxyz usuario/servidorxyz:latest

# 3) Autenticación con token
read -s TOKEN
echo "$TOKEN" | docker login -u usuario --password-stdin
unset TOKEN

# 4) Publicar
docker push usuario/servidorxyz:1.0
docker push usuario/servidorxyz:latest

# 5) Desplegar desde Docker Hub
docker rmi servidorxyz usuario/servidorxyz:1.0 usuario/servidorxyz:latest
docker compose up -d

# 6) Nueva versión
docker build -t usuario/servidorxyz:1.1 -t usuario/servidorxyz:latest .
docker push usuario/servidorxyz:1.1
docker push usuario/servidorxyz:latest

# 7) Ver digests
docker images --digests | grep servidorxyz

# 8) Cerrar
docker compose down
docker logout

    17. Reto final (sin guía)

    Ahora hazlo tú solo:

    1. Crea un repositorio nuevo en Docker Hub llamado apachexyz.
    2. La imagen debe partir de httpd:2.4-alpine. Busca en la documentación de la imagen oficial en qué directorio sirve las webs Apache.
    3. Publica las versiones 1.0 y 2.0 (con contenidos distintos) y latest apuntando a la 2.0.
    4. Escribe un compose.yaml que levante a la vez tu servidorxyz:1.1 en el puerto 8080 y tu apachexyz:1.0 en el 8081.

    18. Entrega

    El alumno entregará:

    1. El fichero compose.yaml del reto.
    2. Las URL de sus dos repositorios en Docker Hub:
      https://hub.docker.com/r/usuario/servidorxyz
      https://hub.docker.com/r/usuario/apachexyz
    3. Captura de pantalla de cada repositorio mostrando sus etiquetas y que es Public.
    4. Las respuestas a las 8 preguntas de la guía.

    Cómo lo comprobará el profesor

    En una máquina sin tus imágenes ejecutará docker compose up -d con tu compose.yaml. Deben descargarse las dos imágenes (Pulled) y responder http://IPSERVER:8080 y http://IPSERVER:8081.

    Resultado de la práctica

    Has publicado en Docker Hub una imagen propia con varias versiones, la has desplegado en una máquina limpia solo con docker compose, has hecho un rollback y has fijado un despliegue por digest. Es el mismo ciclo que en la Ud7 automatizarás con un pipeline de CI/CD.
